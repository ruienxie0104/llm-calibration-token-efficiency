# 研究流程總整理 — 從頭到尾的連貫敘事

> 2026-09-11 更新
> 目標：把每一階段的實驗串成一條連貫的故事線

---

## 核心問題只有一個

**校準品質能不能幫助 LLM 更有效率地使用 token？**

這個問題從研究第一天到現在都沒變。變的是我們對這個問題的理解——以及我們發現這個問題比想像中更複雜。

---

## 第一條故事線：Phase 3 之前（V1 → V2 → Deep Research）

### 在做什麼？

建立實驗基礎：確認工具（PM）能用、建立校準測量方法（LCAE、Brier）、確認競爭者定位。

### 發現了什麼

- PM 能區分推理風格
- 信心 prompt 需要多輪對話，無上下文會失真
- 該領域 2025-2026 快速升溫，需要收斂定位

### 跟核心問題的關係

工具和方法論的準備階段，還沒有回答核心問題。

---

## 第二條故事線：Phase 2 + Phase 3（核心實驗）

### 在做什麼？

用 Controlled Budget Sweep 讓模型在不同 token 預算下回答同一題，看校準品質是否影響低預算下的表現。

### 發現了什麼

**發現一（Phase 2）：** Budget sensitivity 存在。DeepSeek 在 256 下表現遠優於 GPT-20B（15% vs 3%）。

**發現二（Phase 3）：** 能力 θ 和校準 LCAE 是兩個獨立維度。DeepSeek 能力最強（θ=+0.65）但校準不是最好；GPT-120B 能力中等但校準最好（LCAE=0.247）。

**發現三（Phase 3）：** Brier 和 LCAE 給出不同的校準排名——選擇哪個指標會影響你對「哪個模型最可靠」的判斷。

**發現四（Phase 3）：** 信心差距可以做為簡單校準代理指標，排序與 LCAE 一致。

### 跟核心問題的關係

看起來校準品質和 token 效率有關係，但關係不是直接的——DeepSeek 贏在推理效率（每步 token 少）而不是校準。這讓核心假設只對了一半。

---

## 第三條故事線：IDS Intervention

### 為什麼要做

Kimiko 指出 Phase 3 只能說「觀察到校準和效率有關聯」，不能說「改善校準就能改善效率」。IDS 是學姐的方法，可以做因果驗證。

### 發現了什麼

IDS 改善了校準（Brier 下降、答錯信心下降），但準確率沒有顯著變化。

### 跟核心問題的關係

因果鏈在校準改善這一步是成立的，但在從校準改善到效率改善這一步斷了。我們需要解釋為什麼。

---

## 第四條故事線：PM 分析

### 為什麼要做

Kimiko 問了一個關鍵問題：低預算下模型到底是「不知道該在哪裡停」還是「根本算不出來」？

### 發現了什麼

256 tokens 下模型平均只產出 1-2 個 step，answer activity 全部為 0%。不是分配決策的問題——是被 `num_predict` 強制截斷。

活動分佈在 256 和 1024 之間比例相似，只是沒機會走到 answer/verify。

DeepSeek 的優勢是每步 token 少，被截斷時損失較小，不是因為校準好。

### 跟核心問題的關係

**這解釋了為什麼核心假設只對了一半：** 我們的實驗設計（硬截斷）從來沒有讓模型做過「分配」決策。模型不知道有預算限制，輸出只是被切斷。所以測量的不是「token 分配效率」而是「推理被截斷後的殘存準確率」。

---

## 整條故事線長這樣

```
核心問題：校準品質能否幫助 LLM 更有效率地使用 token？
  │
  ├─ Phase 2+3：觀察到校準和能力是兩個獨立維度
  │       ↓
  ├─ IDS：校準可以被改善，但改善沒有轉換成效率
  │       ↓
  ├─ PM 分析：因為實驗設計（硬截斷）沒有給模型分配 agency
  │       ↓
  └─ 結論：核心假設未被否定，但也未被驗證
            ─ 實驗設計本身揭示了「預算機制的類型」是一個被忽略的變數
            ─ 未來研究需要區分 hard constraint 和 soft constraint
```

## 一句話總結

> 我們想驗證「校準好 → token 效率好」，但發現實驗設計（硬截斷）讓模型沒有機會做分配決策。這個發現本身揭示了現有研究的 gap：hard constraint 和 soft constraint 是兩種不同的預算機制，文獻中從未被明確區分過。

前後是連貫的，每一階段的實驗都有一個明確的「為什麼做」和「學到了什麼」，而且每一步都在回答上一步留下的疑問。
