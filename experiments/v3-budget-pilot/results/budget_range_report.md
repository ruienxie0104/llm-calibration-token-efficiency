# Budget-Range Pilot 報告

> 2026-09-16
> 目的：掃描 GPT-OSS-120B 在 6 種 Soft budget 下的實際成本與收益
> 360 次 API 呼叫，無 confidence calls

---

## 一、為什麼做這輪實驗

Step 0 發現 Soft 256/512 的實際成本差只有 126 tokens（GPT-120B），不足以產生可預測的 gain 變異。本輪掃描 6 個 budget 等級（64 到 2048），確認 Soft prompt 是否能真正控制推理 token 成本。

---

## 二、結果

### 2.1 每個 Budget 的表現

| Budget | 準確率 | 平均 Token | 中位數 Token | 範圍 | 超過預算 | 解析率 |
|--------|-------|-----------|-------------|------|---------|-------|
| **64** | 85.0% | **446** | 358 | 145-1814 | **60/60 (100%)** | 100% |
| 128 | 85.0% | **549** | 398 | 138-3204 | 59/60 (98%) | 100% |
| 256 | **86.7%** | **542** | 418 | 185-1518 | 43/60 (72%) | 100% |
| 512 | 85.0% | **663** | 482 | 163-3984 | 24/60 (40%) | 100% |
| 1024 | **86.7%** | **741** | 479 | 196-3911 | 14/60 (23%) | 100% |
| 2048 | 85.0% | **780** | 494 | 200-4096 | 3/60 (5%) | 98% |

### 2.2 核心發現

**發現一：Soft prompt 無法控制成本。**

提示寫 64 tokens，模型平均花 446 tokens，100% 超過預算。提示寫 2048 tokens，平均花 780 tokens。兩者只差 334 tokens，但預算差了 32 倍。

**發現二：準確率完全不隨預算變動。**

64 到 2048 的準確率都在 85-87%，標準差為 0。這代表模型是否遵守預算指示，跟答對率完全無關——它已經決定了要花多少 token 推理，不會因為 prompt 寫了不同的數字就改變。

**發現三：`done_reason` 全部為 `stop`，沒有 `length`。**

沒有任何一次呼叫因為長度上限被截斷（因為 API safety cap 設在 4096）。所有回答都是模型自願停止的。這進一步確認了「不是 API 在控制，是模型自己在決定花多少 token」。

---

## 三、跟 Phase 3 Hard 的對比

| 指標 | Soft 64 | Soft 2048 | Hard 256 | Hard 1024 |
|------|---------|-----------|----------|-----------|
| 準確率 | 85% | 85% | 0% | 48% |
| 平均 Token | 446 | 780 | 256 | 778 |

Soft 不管設多少預算，模型都花 450-780 token、85% 準確。Hard 下 256 時 0%、1024 時 48%。**Hard 才是真正能控制成本的介面。**

---

## 四、結論

> **Soft prompt 不是可靠的成本控制機制。GPT-OSS-120B 幾乎完全忽略預算指示。**

這輪 360 次呼叫的結論非常清楚，不需要再做更多 Soft scan。後續若要研究 token allocation，應使用：

1. **Hard cap（`num_predict`）**：已在 Phase 3 驗證過，成本可控
2. **Sampling-based compute**：控制抽樣次數而非推理長度
