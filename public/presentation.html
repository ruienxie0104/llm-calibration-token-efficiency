研究起源

從學姐 LCAE 框架到我的研究問題

學姐論文：LCAE 框架

Chen, T.-Y. et al., Latent Confidence Alignment for LLM Self-Assessment. IEEE IRI 2026.

IRT 能力估計→ 自我評估情境→ LCAE 指標→ 模型選擇

核心是 IRT Rasch Model：把模型能力和題目難度放在同一把尺：

P(答對) = σ(模型能力 θm − 題目難度 βi)
階段內容關鍵發現
Stage 1
IRT 能力估計		Rasch Model 同時估計模型能力 θ 與題目難度 β客觀計算模型在每題的答錯機率
Stage 2
自我評估		四種情境：QOQ / IDS / DPR / CombinedIDS（給難度訊號）最有效；改善校準不傷能力
Stage 3
模型選擇		LCAE 比較自估 vs IRT 客觀估計能力強 ≠ 自評準；提及 cost 但未驗證
關鍵：GPT-5 能力最強但自評不是最好；Llama 3 70B 自評最準。能力強不等於知道自己會不會。

引入 Process Mining（流程挖掘）

把模型的 Chain-of-Thought 切成活動序列，用 pm4py 做流程分析

「先理解題意…路程120公里、時間2小時…速度=60 km/h…驗證…答案選B」
→ understand → recall → calculate → verify → answer

分析面向：Petri Net 發現 / 一致性檢查 / 熵分析 + JSD

重點：不是只看 token 總數，而是看推理的 結構 — 先理解還是直接算？有沒有驗證？有沒有回頭修正？

過程中的重要轉折：Bug 修正與數據翻轉

V2 執行後發現多個程式 bug，進行了完整 rebuild。修正後的數據與初版完全不同。

Bug原本問題修正
Conformance讀取不存在欄位 → alignment 全 0只計 log/model move
Levenshtein(A,B) 和 (B,A) 分別抽樣 → 非對稱矩陣對稱寫入，對角線=0
JSDdistance 被標成 divergencedistance² = divergence
Confidence只傳 response，截斷 500 字完整 thinking+response

Rebuild 前（有 bug）

  • GPT-20B 準確率 56%
  • 信心差距 +33~+81
  • 「反相關」核心發現
  • Alignment 全 0

Rebuild 後（已修正）

  • GPT-20B 準確率 98%
  • 信心差距 −0.8~+4.5
  • 前版發現被推翻
  • Alignment 有數字
教訓：V2 校準分析價值下降（準確率變異消失），但 PM pipeline 驗證成功。重要的是暴露了 prompt sensitivity、confidence scarcity、Petri net flower model 等問題，後續實驗不會重複犯錯。

核心：V3 Budget Sensitivity Pilot

MATH-500 · 30 題 · 2 模型 · 4 Budgets · 480 次呼叫

實驗設計

參數設定理由
題目30 題 MATH-500（Level 3-5 各 10）MATH 是標準 benchmark；Level 1-2 太簡單
模型GPT-OSS-20B vs DeepSeek校準差 vs 校準好，兩極端最大化差異
Budgets128 / 256 / 512 / 1024根據 V2 自然用量 ~600-900 tokens 設定
複製每條件 2 次 replicate檢查隨機波動
控制Ollama num_predict, temp=0.0真正事前限制，非事後截斷
Budget 邏輯：自然 ~600-900 → 128 是極度壓縮（~15%）、256 顯著壓縮（~30%）、512 中等（~60%）、1024 接近無限制。保證看到「不足到充足」的連續變化。

主要結果

480 次呼叫，約 11 分鐘完成

1280 / 60 = 0.0%0 / 60 = 0.0%—題目夠難
2562 / 60 = 3.3%9 / 60 = 15.0%5.0×🏆 最大差距！校準優勢顯現
51212 / 60 = 20.0%20 / 60 = 33.3%1.7×差距縮小
102419 / 60 = 31.7%22 / 60 = 36.7%1.2×接近飽和
核心發現：校準品質在低資源時差異最明顯。256 時 DeepSeek 15% vs GPT 3%（5 倍差），但 1024 時差距僅 1.2 倍。當 token 無限，大家都差不多；但資源受限時，校準好的模型更會把有限的 token 用在對的地方。

V3 Pilot 結論

  • Budget sensitivity 確認存在 — 128→1024 穩定爬升，MATH-500 L3-5 難度剛好
  • DeepSeek 在所有 budget 下優於 GPT — 256 差距最大（5 倍），1024 趨近（1.2 倍）
  • 校準優勢在低 token 時最明顯 — 資源受限時差異擴大，論文核心論點有初步支持
  • 逐題分析：8 題 DS 比 GPT 省 token，僅 1 題反過來
  • 只有 2 個模型 — 無法區分校準 vs 模型能力的 confound（大小、架構也不同）
  • 無 confidence 收集 — 還不能驗證校準品質與 token requirement 的因果關係
  • 18/30 題連 1024 都做不出 — 部分題目對實驗無貢獻
總結：方向對了（Go ✅），但還需要一個決定性實驗才能確認校準的獨立價值。

下一步：Phase 3 決定性實驗

Phase 3：區分校準 vs 模型能力的 Confound

目前無法區分看到的差異來自「校準品質」還是單純「模型能力」— 加入兩個中間模型就能解開這個 confound。

參數設定目的
模型4 個（+GPT-120B, +GLM-5.2）區分校準 vs 能力的 confound
題目60 題 MATH-500 L3+L4剔除太難（L5）的題目
Budgets3 個（256/512/1024）剔除 128（0% 無資訊量）
信心收集加入多輪對話式自評驗證校準品質與 requirement 的關係
複製3 次 replicate提高高 budget 信度
關鍵預測：如果 GLM-5.2（最好校準）在低 budget 勝 DeepSeek，且 GPT-120B（中等校準）接近 GPT-20B → 校準是獨立解釋變數。如果只是模型大小排序 → 方向需要調整。
